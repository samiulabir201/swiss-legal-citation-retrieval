## Pipeline

1. Cell 0 (setup): pip install + uninstall `flashinfer`/`flashinfer-python`; prompts the user to restart the kernel before continuing.
2. Cell 1 (imports): `pandas`, `tqdm`, `torch`; prints CUDA device info (recorded: 2x Tesla T4, ~14.46 GiB free each).
3. Cell 2 (config): instantiates `Config`, sets CUDA env per `gpu_mode`, asserts `model_path` exists, mkdirs `output_dir`, builds output filenames, prints config + JSONL path.
4. Cell 3 (data load): `resolve_input_path()` finds the CSV; selects rows; renders a preview of the first 20 selected.
5. Cell 4 (schema/prompts): defines `DESCRIPTOR_KEYS` (16 keys), allowed `ROLE_VALUES` (11 roles), `LLM_SCHEMA_HINT`, `SYSTEM_PROMPT` (Swiss legal descriptor extractor that explicitly forbids questions, summaries, statute anchors, case anchors, outcome, retrieval views; English classification fields; source-language `terms_original`), `USER_TEMPLATE`, `trim_text`, `build_user_prompt`.
6. Cell 5 (parsing/normalization): `extract_json_object` (strips ``` fences and `<think>` blocks, walks the first balanced `{...}` block, falls back through `json.loads` -> trailing-comma scrub -> `ast.literal_eval`); `clean_str`, `clean_list` (dedupe casefold, length-cap); `normalize_descriptor` enforces field types/lengths, validates `paragraph_role` against `ROLE_VALUES` (else `'neutral'`), clamps `specificity_score` to `[0,1]`, strips a hard-coded `forbidden` set of fields; `empty_descriptor(error)` returns a zero descriptor carrying `_descriptor_error`.
7. Cell 6 (dual-worker launcher, `gpu_mode == 'dual_worker'` only): writes `vllm_dual_worker.py` (a self-contained worker that re-implements imports/config/data load/schema/parser/vLLM load and runs the per-shard descriptor loop), splits `work_df` in half by row count, builds two `shards` (GPU 0 first half, GPU 1 second half), launches each via `subprocess.Popen` with safety-capped args, polls `p.poll()` every 30s, prints `--- Last 120 lines ---` of any failed worker log, merges per-shard JSONL (sorted by `_source_row`), reconstructs `failures`/`preview_df`, writes the unified outputs (`output_jsonl`, `output_failures_jsonl`, `output_preview_csv`, `output_metrics_json` with `mode='dual_worker'` and per-worker metrics). Sets `DUAL_WORKER_DONE=True`; otherwise prints a skip message.
8. Cell 7 (vLLM load, `gpu_mode != 'dual_worker'`): loads `AutoTokenizer` (with `trust_remote_code=True`) and instantiates `vllm.LLM(...)` with the config kwargs; tries to attach an explicit `AttentionConfig(backend='TRITON_ATTN'/'triton_attn')` and falls back to env-only if unavailable.
9. Cell 8 (generation helpers): `render_prompt` (chat template with system + user, optional repair user prompt with prior parser error and bad output, tries `enable_thinking=False`); `generate_raw(prompts, max_tokens)` uses a shared `SamplingParams(temperature, top_p, max_tokens, repetition_penalty)` and returns first-output text per prompt; `generate_descriptor` parses the raw output, retries up to `max_retries` with a repair prompt at `retry_max_new_tokens`, returning `(desc, gen)` where `gen.status in {'ok','ok_after_retry','failed_descriptor_parse'}` and failure paths return `empty_descriptor`.
10. Cell 9 (main loop, `gpu_mode != 'dual_worker'`): iterates `work_df` in batches of `cfg.batch_size`, builds prompts, calls `generate_raw`; on batch failure falls back to per-row generation; per row produces a record `{_source_row, citation, text, llm_enrichment, llm_generation:{model, method:'minimal_descriptor_only', ...gen}}`; appends failures; writes `output_jsonl` line-delimited, deletes/writes `output_failures_jsonl`, builds a `preview_df` (joins list fields with `' | '`), writes `output_preview_csv`, writes `output_metrics_json` (`selected_rows`, `written_rows`, `failures`, `elapsed_seconds`, `rows_per_second`, `status_counts`, paths); displays metrics and the preview. When `dual_worker` already wrote outputs, this cell reads them back from disk instead.
11. Cell 10 (QC): scans every emitted record for fields in `FORBIDDEN` (= the same forbidden set as `normalize_descriptor`), reports per-row `forbidden_fields`, `concept_count`, `terms_original_count`, `has_topic`, `specificity_score`; prints counts of rows with forbidden fields and failed-status rows.
12. Cell 11 (markdown): instructs that the JSONL is then consumed by a local `normalize_enriched_court_row(...)` finalizer that adds `rag_enrichment`, `normalized_anchors`, `anchor_quality_flags`, `retrieval_views`, `enrichment_quality`.

## Summary

This notebook is the Kaggle-side, GPU-only stage of the court-considerations enrichment pipeline: it loads `court_considerations.csv`, runs Qwen3-8B-AWQ via vLLM with a strict descriptor-only prompt (English classification fields plus source-language `terms_original`, explicit forbids on anchors/outcomes/summaries/queries), and writes a raw `court_llm_descriptors_*.jsonl` line-delimited file plus preview CSV, failures JSONL, and metrics JSON for a downstream local finalizer to merge with the source CSV. Compared with the sibling `court_llm_descriptor_kaggle.md` notebook, the entry point defaults to `cfg.gpu_mode='tp2'` (one vLLM engine across both T4s) and adds an opt-in `'dual_worker'` mode that shells out two GPU-pinned subprocesses with conservative safety caps to avoid Kaggle's 30 GiB host-RAM ceiling. Generation is deterministic (`temperature=0`, `top_p=1`, `repetition_penalty=1.02`), with up to one repair retry that re-injects the parser error and bad output; parsing strips Markdown fences and `<think>` blocks before walking the first balanced JSON object, with trailing-comma scrub and `ast.literal_eval` fallbacks. The recorded run was actually started in `gpu_mode='single'` against 50 rows of BGE 139 I 2 paragraphs and the saved outputs show vLLM loaded cleanly but the batch loop is captured at 0/13 — the metrics, preview, and QC artifacts were not produced in this saved cell state.
