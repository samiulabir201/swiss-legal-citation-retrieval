## Configuration

- Hardware target: RTX PRO 6000 Blackwell Server Edition (SM 12.0, ~95 GB), Colab runtime, CUDA 13.0 wheels (`cu130` FlashInfer index).
- Model: `Qwen/Qwen3-8B-AWQ` (`quantization='awq_marlin'`), tokenizer via `transformers>=4.51.0`, `enable_thinking=False`, temperature 0.0, top_p 1.0, `repetition_penalty=1.0`.
- vLLM engine (`vllm>=0.10.0`, observed 0.11+ path): `tensor_parallel_size=1`, `gpu_memory_utilization=0.95`, `max_model_len=2048`, `max_num_seqs=384`, `submit_chunk=4096`, `enforce_eager=False`, `disable_custom_all_reduce=True`, `enable_prefix_caching=True`, `disable_log_stats=True`, `download_dir` under Drive `models/huggingface`.

- Speculative decoding: `enable_ngram_speculation=False` (`speculative_num_tokens=5`, `speculative_ngram_min=2`, `speculative_ngram_max=4` defaults), disabled because the ngram path forces synchronous worker init that is buggy on this AWQ+SM 12.0 combo.
- Structured outputs: `use_structured_outputs=True` via xgrammar. Cell 7 resolves the API at import time, preferring `vllm.sampling_params.StructuredOutputsParams` (vLLM 0.11+) over `GuidedDecodingParams` (0.10). The formal JSON schema `DESCRIPTOR_JSON_SCHEMA` constrains 16 keys with explicit `maxLength`/`maxItems` bounds and a `paragraph_role` enum drawn from `ROLE_VALUES`.
- Generation: `max_new_tokens=288` (sits above observed P99 ~280 tok, avg 229), `retry_max_new_tokens=384`, `max_retries=1`, single per-row repair retry through `parse_or_retry`. `include_raw_output_on_success=False`.
- Input slice: `start=0`, `limit=10_000`, `sample_random=False`, `random_seed=42`, `min_text_chars=80`, `max_text_chars=2400` (head+tail truncation via `trim_text`).
- Paths: `BASE_DIR=/content/drive/MyDrive/swiss_law`, input `data/court_considerations.csv`, hot-path JSONL on `/content/scratch_outputs`, final copy to `outputs/court_llm_descriptors_0000000_0009999.{jsonl,_preview.csv,_failures.jsonl,_metrics.json}`.
- Env vars set: `VLLM_WORKER_MULTIPROC_METHOD=spawn`, `FLASHINFER_DISABLE_VERSION_CHECK=1`, `CUDA_VISIBLE_DEVICES=0`, `TOKENIZERS_PARALLELISM=false`, optional `VLLM_USE_FLASHINFER_SAMPLER=1` when FlashInfer is requested; debug toggle `DEBUG_VLLM_WORKER=False` (would set `VLLM_LOGGING_LEVEL=DEBUG` and `CUDA_LAUNCH_BLOCKING=1`).

## Pipeline

1. **Cell 0 (markdown):** Documents the FP8-KV crash diagnosis (3 runs → silent worker death on FP8 KV; FP16 KV stable at 17.94 rows/sec baseline), the v4 changes (`use_structured_outputs=True`, `max_new_tokens 320→288`, `gpu_memory_utilization 0.92→0.95`, `submit_chunk 2048→4096`, `repetition_penalty 1.02→1.0`), and the `DEBUG_VLLM_WORKER` toggle.
2. **Cell 1 (Colab setup):** Mounts Drive, pip-installs `vllm>=0.10.0`, `transformers>=4.51.0`, `accelerate`, `safetensors`, `pandas`, `tqdm`, `huggingface_hub`. `_detect_cuda_index_suffix` maps `torch.version.cuda` to a supported FlashInfer wheel index (cu126..cu131, fall-back to highest <= detected). `_install_flashinfer` pins `-python`+`-cubin` together, then installs `-jit-cache`. Sets `FLASHINFER_DISABLE_VERSION_CHECK=1` and instructs the user to restart the runtime once after first install.
3. **Cell 2 (imports + runtime check):** Sets vLLM env vars before any CUDA-touching call. Deliberately avoids `torch.cuda.*` calls. Reads GPU info via `nvidia-smi --query-gpu=...` (`GPU_COMPUTE_CAPABILITY`, `GPU_NAME`). Imports `flashinfer` (Python-level only) and derives `FLASHINFER_USABLE` by disabling on SM 12.x.
4. **Cell 3 (config):** Builds the `Config` dataclass and resolves paths (`base_dir`, `data_dir`, `out_dir`, `local_scratch`, `model_download_dir`), sets `CUDA_VISIBLE_DEVICES` per `gpu_mode`, and computes the output suffix `{start:07d}_{end:07d}`.
5. **Cell 4 (load CSV):** `resolve_input_path` searches multiple candidate locations and glob-walks `DATA_DIR`/`BASE_DIR`/`/content` if needed. Drops null/short rows, prints length distribution, slices via iloc or `pd.sample`, resets index to `_source_row`.
6. **Cell 5 (schema/prompt):** Defines `DESCRIPTOR_KEYS`, `ROLE_VALUES`, `LLM_SCHEMA_HINT`, `SYSTEM_PROMPT` (now embeds the schema JSON so the entire system+schema prefix is prefix-cacheable), `USER_TEMPLATE` (variable per-row content only), `DESCRIPTOR_JSON_SCHEMA` for xgrammar guided decoding, plus `trim_text` and `build_user_prompt`.
7. **Cell 6 (parser):** `extract_json_object` strips Markdown fences and `<think>` tags, then balanced-brace-scans to extract one JSON object with a JSON5-style trailing-comma fallback and `ast.literal_eval` last resort. `clean_str`, `clean_list`, `normalize_descriptor` (with `FORBIDDEN` key stripping and `paragraph_role` mapping), and `empty_descriptor(error)` enforce the canonical shape.
8. **Cell 7 (load vLLM, single attempt):** Loads tokenizer with the model cache dir, probes the chat-templated system+schema prefix to log its token count, inspects `LLM.__init__` signature for `attention_backend`/`attention_config`, assembles `llm_kwargs` (passes `kv_cache_dtype`, `enable_prefix_caching=True`, optional `speculative_config` for ngram), and constructs `LLM(**llm_kwargs)` in a single try block with an ordered diagnostic checklist on failure.
9. **Cell 8 (generation helpers):** Resolves the structured-outputs API (`StructuredOutputsParams` vs `GuidedDecodingParams`), pre-builds `_STRUCTURED_OUT`, exposes `_make_sampling_params`, `render_prompt(repair, bad_output, error)`, `generate_raw`, `generate_raw_safe` (OOM-recursive split), and `parse_or_retry` (per-row repair path). Runs a 16-prompt warm-up to capture CUDA graphs.
10. **Cell 9 (main loop):** Iterates `work_df` in `submit_chunk=4096` slices, calling `llm.generate(prompts, sampling_params=params, use_tqdm=False)` once per chunk so vLLM continuous-batches up to 384 concurrent sequences. Accounts `prompt_token_ids` and `outputs[0].token_ids` for token metrics. Writes records (`{_source_row, citation, text, llm_enrichment, llm_generation}`) to `local_jsonl` and flushes per-chunk. After processing: copies to Drive, dumps `failures` JSONL (only if any), writes a 18-column preview CSV (capped at 1,000 records), and writes the `metrics.json`.
11. **Cell 10 (QC):** Re-reads the produced JSONL, walks every record with `find_forbidden` to verify no forbidden keys leak through, and reports per-status counts and forbidden-row counts.
12. **Cell 11 (markdown tuning notes):** Post-baseline diagnosis advice (KV-cache, structured-outputs, gpu_memory_utilization fallbacks; ngram speculation experiment; schema-edit reminder to keep `LLM_SCHEMA_HINT` and `DESCRIPTOR_JSON_SCHEMA` in sync).

## Summary

This v4 notebook runs a 10,000-row baseline of Qwen3-8B-AWQ descriptor extraction over Swiss court considerations on an RTX PRO 6000 Blackwell Server (SM 12.0) Colab session, using vLLM with FP16 KV cache, awq_marlin quantization, prefix caching, and xgrammar guided decoding against a strict 16-key JSON schema. The configuration deliberately disables FP8 KV (three prior runs proved it silently kills the vLLM worker on this AWQ+SM 12.0 stack) and disables FlashInfer (0.6.x ships no SM 12.x kernels), letting vLLM auto-select FlashAttention 4. End-to-end the slice completed in 639.4 s for 10,000 rows = 15.64 rows/sec (14,631 total tok/s, 3,579 output tok/s) with 9,969 ok / 27 ok_after_retry / 4 failed parses and zero forbidden-field leaks per the QC pass. Observed prompt avg 707 tok and output avg 229 tok validate the system+schema-in-system-prompt prefix-caching design (~315 cached tokens) and the `max_new_tokens=288` choice. Realized throughput sits below the 17.94 rows/sec FP16 baseline cited in the markdown plan (the structured-outputs + larger queue changes were expected to lift it to 28–40 rows/sec); the markdown tuning notes point at structured-outputs compilation, submit_chunk, and ngram speculation as next levers.
