## Pipeline

- **Cell 4** — `DESCRIPTOR_KEYS` lists 16 minimal descriptor fields: `legal_area`, `primary_domain`, `secondary_domain`, `legal_domain_path`, `topic`, `subtopic`, `micro_topic`, `concepts_en`, `terms_original`, `doctrinal_rule`, `legal_test`, `fact_pattern_tags`, `procedural_context`, `paragraph_role`, `authority_role`, `specificity_score`. `ROLE_VALUES` enumerates 11 allowed `paragraph_role` strings (`holding`, `reasoning`, `facts`, `procedural_history`, `legal_standard`, `application`, `citation`, `costs`, `notification`, `disposition`, `neutral`). `LLM_SCHEMA_HINT` gives per-field length/format guidance injected into the prompt. `SYSTEM_PROMPT` instructs the model to return one compact JSON object, English for classification fields, exact source-language terms for `terms_original`, and explicitly forbids generating questions, summaries, statute/case anchors, outcome, and retrieval views. `USER_TEMPLATE` interpolates citation, trimmed text, and the JSON schema. `trim_text()` collapses whitespace and head/tail truncates with a ` ... [TRUNCATED] ... ` marker when over `max_text_chars`.

- **Cell 5** — `extract_json_object(raw)` strips ```` ``` ```` fences and `<think>` blocks, then walks the string to find a balanced JSON object; on `json.loads` failure it removes trailing commas and falls back to `ast.literal_eval`. `clean_str()` collapses whitespace and truncates; `clean_list()` deduplicates case-insensitively up to `max_items`. `normalize_descriptor()` coerces every field with bounded lengths, maps `paragraph_role` to lowercase underscored form and falls back to `'neutral'` if not in `ROLE_VALUES`, clamps `specificity_score` to `[0,1]`, and pops a forbidden set (`statute_anchors`, `case_anchors`, `normalized_anchors`, `retrieval_views`, `outcome_signal`, `query_phrases_en`, `natural_language_queries`, `legal_question`, `summary_en`, `english_summary`, `enrichment_quality`, `anchor_quality_flags`) as a hard guarantee. `empty_descriptor(error)` returns a zero-valued descriptor with `_descriptor_error`.

- **Cell 6b (dual-T4 launcher)** — Active only when `cfg.gpu_mode == 'dual_worker'`. Writes a standalone worker script to `/kaggle/working/vllm_dual_worker.py` that re-embeds Cells 1-8 with `argparse` driven `--gpu-id`, `--start`, `--limit`, `--tag`, model/input/output overrides, batch/seq/memory/length overrides. The launcher splits `total_rows` into halves (`first_count = (total_rows + 1) // 2`), spawns one `subprocess.Popen` per shard with `CUDA_VISIBLE_DEVICES=<gpu_id>`, `PYTHONUNBUFFERED=1`, `VLLM_WORKER_MULTIPROC_METHOD=spawn`, `VLLM_ATTENTION_BACKEND=TRITON_ATTN`. Logs streamed to `vllm_worker_gpu{0,1}.log`. The cell polls `p.poll()` every 30 s, prints last 120 log lines and raises `RuntimeError` on any non-zero return code. On success it concatenates the per-shard JSONLs sorted by `_source_row`, rewrites the unified `output_jsonl`, regenerates the preview CSV and a merged `metrics` dict carrying `mode='dual_worker'`, `elapsed_seconds_parallel_wall_estimate`, per-shard `worker_metrics`, `part_paths`, `worker_logs`, and sets `DUAL_WORKER_DONE = True`. If `gpu_mode != 'dual_worker'`, sets `DUAL_WORKER_DONE = False` and prints a skip message.

- **Cell 6c (single/tp2 vLLM load)** — Skipped when `dual_worker`; otherwise loads `AutoTokenizer` and instantiates `vllm.LLM` with `model`, `tensor_parallel_size`, `gpu_memory_utilization`, `max_model_len`, `max_num_seqs`, `enforce_eager`, `quantization='awq_marlin'`, `disable_custom_all_reduce=True`, `disable_log_stats=True`. Tries to attach `AttentionConfig(backend='TRITON_ATTN')` (with a `'triton_attn'` fallback), with a graceful `except` if `vllm.config.AttentionConfig` is unavailable.

- **Cell 7** — `render_prompt(citation, text, repair, bad_output, error)` builds the user prompt; when `repair=True` it prepends the previous error and bad output and asks for one complete repaired JSON object. `tokenizer.apply_chat_template` is called with `enable_thinking=cfg.enable_thinking`, falling back to a `TypeError`-safe call without that kwarg. `generate_raw(prompts, max_tokens)` calls `llm.generate` with `SamplingParams(temperature, top_p, max_tokens, repetition_penalty)` and `use_tqdm=False`, returning first-output text per request. `generate_descriptor(citation, text, first_raw)` loops up to `cfg.max_retries + 1`: tries `extract_json_object` → `normalize_descriptor` on `raw`, and on exception records the attempt and regenerates with the repair prompt; on final failure returns `empty_descriptor(err)` and a `failed_descriptor_parse` status with `attempts` log.

- **Cell 8 (extraction loop)** — Skipped when `dual_worker` (in that case loads the merged JSONL from disk). Otherwise iterates `work_df` in `cfg.batch_size` slices; for each batch it builds `row_objs` (with `_source_row`, `citation`, `text`) and `prompts`, calls `generate_raw(prompts, cfg.max_new_tokens)`, then per-row calls `generate_descriptor(..., first_raw=raw)`. Each record is `{_source_row, citation, text, llm_enrichment, llm_generation}` where `llm_generation` carries `model`, `method='minimal_descriptor_only'`, plus status/attempt/error from the helper. Records are written to `output_jsonl`, failures (if any) to `output_failures_jsonl`. A flattened preview DataFrame is built (one row per record, joining list fields with `' | '`) and written to `output_preview_csv`. A `metrics` dict with `start`, `limit`, `selected_rows`, `written_rows`, `failures`, `elapsed_seconds`, `rows_per_second`, `status_counts`, output paths is written to `output_metrics_json`, printed, and `preview_df` displayed.

- **Cell 9 (QC)** — `find_forbidden(obj)` recursively walks dicts/lists and flags any of the `FORBIDDEN` keys (`statute_anchors`, `case_anchors`, `normalized_anchors`, `retrieval_views`, `outcome_signal`, `query_phrases_en`, `natural_language_queries`, `legal_question`, `summary_en`, `english_summary`, `enrichment_quality`, `anchor_quality_flags`). Per record produces `{citation, status, forbidden_fields, concept_count, terms_original_count, has_topic, specificity_score}`; displays `qc_df` and prints `Forbidden field rows` and `Failed rows` counts.

- **Trailing markdown** — Next local step: download `court_llm_descriptors_*.jsonl` and call `normalize_enriched_court_row(citation, text, llm_enrichment, deterministic_metadata)` locally to produce final production JSONL with `rag_enrichment`, `normalized_anchors`, `anchor_quality_flags`, `retrieval_views`, `enrichment_quality`.

## Summary

This Kaggle T4 notebook runs only the expensive LLM step of the court-citation enrichment pipeline: it reads `court_considerations.csv`, prompts Qwen3-8B-AWQ via vLLM with a minimal 16-field semantic descriptor schema (legal area / domain / topic / concepts / doctrinal_rule / legal_test / paragraph_role / specificity_score, etc.), and writes raw `court_llm_descriptors_*.jsonl` to be normalized later by local CPU scripts. The design is intentionally narrow — the prompt forbids the LLM from emitting anchors, summaries, outcome signals, or retrieval views, and `normalize_descriptor` plus a recursive QC sweep enforce that no forbidden fields leak through. The default mode is `dual_worker`, which spawns one `vllm.LLM(tensor_parallel_size=1)` subprocess per T4 and merges sorted JSONL shards (fastest for Qwen3-8B-AWQ since the model fits on one T4), with `single` and `tp2` as fallback modes. In the saved execution the run was actually configured in `single` mode with batch_size=4 on 50 rows of `BGE 139 I 2` sub-paragraphs; vLLM loaded successfully in ~57 s on GPU 0 with Triton attention and AWQ-Marlin kernels, but the extraction cell was captured mid-run (no metrics, preview, or QC outputs were saved). The trailing markdown points to a local `normalize_enriched_court_row(...)` finalizer that consumes this JSONL to produce the final production enrichment with `rag_enrichment`, `normalized_anchors`, `anchor_quality_flags`, `retrieval_views`, and `enrichment_quality`.
