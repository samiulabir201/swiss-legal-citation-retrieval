## Pipeline

1. Environment setup: detect Colab, verify GPU, conservative pip install of Pillow/NumPy/SciPy + uv-installed vLLM under a pinned constraints file, mount Drive.
2. Configuration: paths, model id, inference and guardrail knobs, target-file flags, file locations, optional reset.
3. JSON schema + prompts: `RAG_SCHEMA` requires `english_summary`, `legal_topic`, `legal_question`, `legal_rule`, `court_holding`, `factual_context`, `english_legal_concepts` (<=6), `search_keywords` (<=8), `natural_language_queries` (<=3), `paragraph_role` (enum: holding/reasoning/background/cost/procedural/disposition/standard_of_review/obiter), `outcome_signal` (enum: granted/dismissed/inadmissible/remitted/partial/none). `SYSTEM_PROMPT` constrains the model to be a deterministic Swiss legal JSON extractor that uses only references present in metadata or paragraph and emits one complete JSON object without prose, markdown, or chain-of-thought. Deterministic pre-filter regexes: `COST_PROC_RE`, `REMITTAL_RE`, `INADMISSIBLE_RE`, `DISMISSED_RE`, `GRANTED_RE`, `PARTIAL_RE` covering DE/FR/IT.
4. Helpers: `load_target_line_indices`, `build_user_message` (renders `<record><metadata>...<paragraph_original_language>...</record>` envelope), `_stub`, `deterministic_disposition` (auto-labels remittal/inadmissible/dismissed/granted/partial via regex), `deterministic_fallback` (synthesizes summary/topic/keywords from labels, statutes, cases, multilingual terms), `auto_classify` (notification paragraph -> procedural stub; disposition match -> disposition; very short text -> procedural fragment; cost regex match -> cost stub), `stream_input`, `count_lines`, `render_prompt` (uses `apply_chat_template(..., enable_thinking=False)` with a TypeError fallback), `clean_model_json` (strips `</think>`, code fences, and out-of-brace prefix/suffix), `validate_and_normalize_enrichment` (clips field lengths, dedups list items, coerces enum), `validate_reference_grounding` (article-id allowlist from metadata/paragraph plus BGE and docket reference scan; tolerates `Art. 6 f.` <-> `Art. 6f`; rejects ungrounded Art./BGE/docket references), `parse_output_text`.
5. Load model: instantiate vLLM with the kwargs above, build three `SamplingParams` instances (main, retry, smoke) bound to `RAG_SCHEMA` via `StructuredOutputsParams`.
6. Smoke test (`RUN_SMOKE_TEST=True`, `SMOKE_N=8`): picks the first N target rows that are not auto-classified, generates with `smoke_sampling_params`, parses, validates, and validates reference grounding; raises `RuntimeError` if any sample fails.
7. Run enrichment: loads target line indices when `TARGETED_ENRICHMENT and not ENRICH_TARGET_CARD_FILE_ONLY`, reads `CHECKPOINT_FILE`, counts input lines, and if `start >= total_lines` resets the checkpoint to 0 (so a stale checkpoint from a larger prior input does not skip the new compact input); appends to `OUTPUT_FILE`/`FAILED_FILE`. Per row: `auto_classify` writes a deterministic stub when matched; otherwise the row is added to a batch and flushed when `len(pending) >= BATCH_SIZE`. `flush_batch` runs `llm.generate(prompts, sampling_params=sampling_params)`, parses each output with `parse_output_text(..., method='qwen35_35b_a3b_vllm', card=card)`, writes the enriched card on success, captures failures to `FAILED_FILE` via `write_failed` (inline retry disabled), updates `CHECKPOINT_FILE` to the last `line_idx + 1`, and prints throughput stats every 5 batches or whenever there are retries/failures. When `ENRICH_TARGET_CARD_FILE_ONLY=False` and a row is not a target, `WRITE_DETERMINISTIC_FALLBACK_FOR_UNTARGETED=True` causes a deterministic-fallback stub to be written.
8. Verify output: distribution of `paragraph_role`, `outcome_signal`, and `method`, count of rows missing required schema fields, count of `deterministic_fallback_after_parse_failed`, and printing of up to five "bad" example cards. Prints GREEN/RED status. Second verification cell samples three LLM-enriched cards with `'qwen35' in method`.
9. Optional failed-row retry pass (`RUN_FAILED_RETRY_PASS=False`): re-reads `FAILED_FILE`, regenerates each card with `retry_sampling_params` and a "previous generation was invalid" guard, writes recovered rows to `FAILED_RETRY_FILE` and remaining failures to `FAILED_STILL_FILE`.

## Summary

This Colab/Compute-Engine notebook enriches a pre-filtered subset (`court_authority_cards_v4_target_cards.jsonl`, 363,258 rows) of Swiss Federal Tribunal authority cards with English RAG metadata using Qwen3.5-35B-A3B served by vLLM under grammar-constrained JSON decoding, targeting an RTX PRO 6000 Blackwell 96 GB GPU. The setup forces Triton MoE to avoid Blackwell FlashInfer JIT failures, disables Qwen thinking, pins Pillow/NumPy/SciPy to avoid binary-wheel breakage, and uses `StructuredOutputsParams(json=RAG_SCHEMA)` with `MAX_TOKENS=256` and `BATCH_SIZE=64`. The pipeline pre-filters notifications, costs, dispositions, and very short paragraphs via deterministic regex stubs and only sends genuine reasoning paragraphs to the LLM; outputs are validated against a strict schema with reference grounding (Art./BGE/docket numbers must appear in the source) and written with append-mode checkpointing so the run is resumable.
